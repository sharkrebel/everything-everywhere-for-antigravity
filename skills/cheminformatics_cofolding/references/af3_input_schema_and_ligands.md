# AlphaFold 3 & Multi-Engine Co-Folding Input Specification Reference

This guide details input preparation, ligand definition, stereochemistry
escaping, pre-flight conformer verification, and multi-engine runtime/weight
configuration (`af3`, `boltz2`, `boltz-api`, `esmfold2`).

## 1. Input Dialects: AF3, Boltz-2 YAML, and Boltz API (`boltz-2.1`)

Open-source AlphaFold 3 uses `dialect: "alphafold3", version: 1`. It differs
from the web server format by requiring top-level entity dictionaries, explicit
chain IDs, and supporting custom CCD mmCIF definitions:

```json
{
  "name": "Target_Ligand_Complex",
  "modelSeeds": [1],
  "sequences": [
    {
      "protein": {
        "id": "A",
        "sequence": "MKTIIALSYIFCLVFA..."
      }
    },
    {
      "ligand": {
        "id": "L",
        "smiles": "CC(=O)Oc1ccccc1C(=O)O"
      }
    },
    {
      "ligand": {
        "id": "M",
        "ccdCodes": ["MG"]
      }
    }
  ],
  "dialect": "alphafold3",
  "version": 1
}
```

The hosted **Boltz API (`boltz-2.1`)** uses an `entities` array plus optional
`binding`, `constraints`, `bonds`, and `num_samples` blocks (automatically
generated by `prepare_cofolding_input.py --output-boltz-api-json` or converted
on the fly from AF3 JSON by `run_cofolding_inference.py --engine boltz-api`):

```json
{
  "entities": [
    {
      "type": "protein",
      "value": "MKTIIALSYIFCLVFA...",
      "chain_ids": ["A"]
    },
    {
      "type": "ligand_smiles",
      "value": "CC(=O)Oc1ccccc1C(=O)O",
      "chain_ids": ["L"]
    }
  ],
  "binding": {
    "type": "ligand_protein_binding",
    "binder_chain_id": "L"
  }
}
```

## 2. Ligand Definition Modes

1.  **SMILES String**:
    -   Ideal for novel screening hits, custom analogs, and synthetic
        derivatives not indexed in PDB CCD.
    -   **Crucial Rule**: SMILES stereochemical slashes (`/` and ``\`) must be
        JSON-escaped (``\\`) to prevent `JSONDecodeError`.
2.  **CCD Codes**:
    -   Ideal for standard cofactors (`ATP`, `NAD`, `HEM`, `SAM`) and metal ions
        (`MG`, `ZN`, `CA`, `FE`).
    -   Defined as `ccdCodes: ["ATP"]` in AF3 JSON and `{"type": "ligand_ccd",
        "value": "ATP", "chain_ids": ["B"]}` in Boltz API JSON.
3.  **Covalent Inhibitors (`bondedAtomPairs` / `bonds`)**:
    -   To link a ligand covalently to an active-site residue (e.g. Cys thiolate
        to an acrylamide warhead): `"bondedAtomPairs": [ [["A", 145, "SG"],
        ["L", 1, "C3"]] ]` (1-based residue indexing in AF3; automatically
        converted to 0-based `polymer_atom` / `ligand_atom` or `smiles_atom`
        endpoints for Boltz API).
4.  **Pocket Constraints (`--pocket-residues`)**:
    -   Pass `--pocket-residues A:42,43,44,67` (1-based residue numbers) to
        `prepare_cofolding_input.py` to emit a Boltz API `pocket` constraint
        (`contact_residues` converted to 0-based indices,
        `max_distance_angstrom: 6.0`).

## 3. Pre-Flight RDKit Conformer Check & Protein–Nucleic Acid Complexes

AlphaFold 3's featurizer attempts to construct an initial 3D RDKit reference
structure for each SMILES ligand. Always run `prepare_cofolding_input.py` first:

```bash
uv run scripts/prepare_cofolding_input.py \
  --name "MY_COMPLEX" \
  --protein A "SEQUENCE" \
  --ligand-smiles L "SMILES" \
  --output-json fold_input.json \
  --output-boltz-yaml fold_input.yaml \
  --output-boltz-api-json fold_boltz_api.json
```

For protein–DNA/RNA complexes, `--dna` and `--rna` are repeatable
(`ID:SEQUENCE`). **Supply each strand of a duplex as its own chain** — AF3 does
not infer the complementary strand:

```bash
uv run scripts/prepare_cofolding_input.py \
  --name "P53_DNA" \
  --protein A "SEQUENCE" \
  --dna C "GGGCATGTCCGGGCATGTCC" \
  --dna D "GGACATGCCCGGACATGCCC" \
  --output-json fold_input.json \
  --output-boltz-yaml fold_input.yaml
```

## 4. Multi-Engine Runtime & Weight Resolution (`af3`, `boltz2`, `boltz-api`, `esmfold2`)

`scripts/run_cofolding_inference.py` supports four co-folding engines via
`--engine <engine>` (default: `af3`):

1.  **`af3` (AlphaFold 3 — Default, Non-Commercial Terms of Use)**:
    -   Resolves model parameters (`af3.bin.zst`) from `--model-dir`,
        `$AF3_MODEL_DIR`, or standard XDG cache directories
        (`~/.cache/alphafold3`, `~/.local/share/alphafold3`).
    -   Requires user acknowledgment of the Google DeepMind AlphaFold 3 Model
        Parameters Terms of Use (`--accept-af3-terms` or
        `.licenses/cheminformatics_cofolding_LICENSE.txt`).
    -   If weights are absent, `--engine af3` stops and prompts for
        `--model-dir`, `--engine boltz2`, or `--engine boltz-api` (never
        silently substituting engines without asking).
2.  **`boltz2` (Boltz-2 — MIT Open-Source Deep-Learning Engine)**:
    -   Joint all-atom protein + ligand diffusion (`boltz predict`), MIT
        license, auto-cached weights (`~/.boltz/`), supporting CUDA GPUs, Apple
        Silicon (`mps`), and laptop CPUs.
    -   `boltz` is declared in the script's PEP 723 `# dependencies` block and
        is resolved automatically when running via `uv run`.
3.  **`boltz-api` (Hosted Boltz-2.1 Structure & Binding Cloud API)**:
    -   Runs cloud-hosted `boltz-2.1` structure and binding affinity predictions
        at `https://api.boltz.bio` via the `boltz-api` Python SDK, `boltz-api`
        CLI, or `polite_http.http_client.HttpClient` REST fallback.
    -   **Credentials (`~/.env`)**: Configure `BOLTZ_API_KEY` (and optional
        `BOLTZ_BASE_URL`, default `https://api.boltz.bio`) in `~/.env` via the
        `credentials` skill (`python-dotenv` loads `~/.env` automatically).
        -   **Live keys** (`sk_bc_admin_live_*`, `sk_bc_ws_live_*`) run real GPU
            inference and incur usage credits.
        -   **Test keys** (`sk_bc_admin_test_*`, `sk_bc_ws_test_*`) return
            synthetic placeholder structures/metrics at zero cost for pipeline
            validation.
    -   **Normalized Outputs & Binding Metrics**: `run_cofolding_inference.py
        --engine boltz-api` writes `<output_dir>/<job_name>_model.cif`,
        `<output_dir>/<job_name>_confidences.json`, and
        `<output_dir>/inference_metadata.json`, which
        `extract_cofolded_complex.py` automatically reads to populate SDF
        properties:
        -   `binding_confidence` (`Boltz_Binding_Confidence`, $0\text{–}1$):
            Probability that binding occurs; primary metric for hit discovery.
        -   `optimization_score` (`Boltz_Optimization_Score`): Relative binding
            strength ranking score for congeneric series lead optimization
            (higher indicates stronger predicted binding).
        -   `structure_confidence` (`Boltz_Structure_Confidence`, $0\text{–}1$),
            `ptm`, `iptm`, `ligand_iptm`, `complex_plddt`, `complex_pde`, and
            `complex_ipde`.
4.  **`esmfold2` (ESMFold2 — OpenProtein All-Atom Complex Co-Folding)**:
    -   All-atom complex co-folding via `openprotein-python`
        (`session.fold.esmfold2` / `session.fold.esmfold2_fast`). Requires
        `OPENPROTEIN_USERNAME` and `OPENPROTEIN_API_KEY` in `~/.env` (configured
        via the `credentials` skill and loaded automatically via
        `python-dotenv`).

### CPU-Only / Apple Silicon Execution

When running without an NVIDIA GPU, pass `--skip-data-pipeline` (`--msa-free` /
`msa: empty`) to bypass MSA database searches and let
`run_cofolding_inference.py` apply laptop CPU/MPS flags, or pass `--engine
boltz-api` to run hosted `boltz-2.1` inference in the cloud.
